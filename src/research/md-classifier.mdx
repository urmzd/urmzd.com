## Motivation

Preliminary self-diagnosis is something most people attempt informally — searching symptoms online and trying to narrow down possible conditions. This project formalizes that process: given a natural language description of symptoms, can a CNN return the most probable medical condition?

## Approach

Two preprocessing pipelines were compared:

- **One-Hot Encoding** — Symptom descriptions were tokenized, stemmed, and encoded into a 56×4210 binary word-stem matrix. Each row represents a condition, each column a unique stem.
- **FastText Embeddings** — An unsupervised FastText model was trained on the corpus to produce dense vector representations of symptom descriptions.

Both pipelines fed into identical CNN architectures. Training data was sourced from UpToDate and Mayo Clinic to ensure clinically grounded symptom-condition mappings.

## Results

The One-Hot pipeline significantly outperformed FastText:

- **Recall:** 90% across conditions
- **Perfect precision** on migraines and tetanus
- **FastText** underperformed because the unsupervised embedding training lost semantic distinctions critical for differentiating similar symptom profiles

The result is counterintuitive — dense learned representations are usually preferred over sparse one-hot encodings. In this case, the small corpus size meant FastText couldn't learn meaningful embeddings, while the one-hot representation preserved every lexical distinction the CNN needed.

## Key Takeaway

Preprocessing choices can dominate model architecture choices when data is limited. The "modern" approach (learned embeddings) failed precisely because it needed more data than was available to learn useful representations. The simpler, higher-dimensional one-hot encoding preserved the information the model needed to discriminate between conditions.
